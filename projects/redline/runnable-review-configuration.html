Runnable review configuration ​

The GitHub Action passes every value to the review tool through environment variables. This is the interim contract; the parsing in src/review/environment.ts is authoritative. When action-owned indexing is enabled, the action fills the code-context variables from its bundled index action; GitHub Action callers do not provide an artifact path.

Environment contract ​

VariableRequiredMeaning
REDLINE_HARNESSreview modeecho, pi, or opencode.
REDLINE_REVIEW_DIRreview modeDirectory holding the context bundle (manifest.json, diffs/, base-files/, …).
REDLINE_SOURCE_DIRreview modeSource-at-head export used for head-file context.
REDLINE_OUTPUT_DIRreview modeDestination for per-file review records and the summary.
REDLINE_CODE_CONTEXToptional in review modePath to a bounded code-context.json artifact. Requires REDLINE_CODE_CONTEXT_REPOSITORY.
REDLINE_CODE_CONTEXT_REPOSITORYwith REDLINE_CODE_CONTEXTExpected owner/name repository identity. Must match the artifact.
REDLINE_MODEL_CONFIGreview modeModel configuration JSON (below).
REDLINE_MODEL_AUTHreview modeProvider-keyed credential map JSON (below). Not consulted when the model config declares auth: "none".
REDLINE_FINDING_SCOPEoptionaldefects (default) or defects-and-risks.
REDLINE_TIMEOUToptionalPer-file model deadline. Duration like 4m, 10m, or 1h30m; default 4m, capped at 360m.
REDLINE_RUN_TIMEOUToptionalWhole-review deadline. Default 10m, capped at 360m. Each model call is capped by the remaining run budget.
REDLINE_REVIEW_CONCURRENCYoptionalMaximum simultaneous per-file model calls. Integer from 1 through 8; default 4.

REDLINE_VERBOSITYoptionalsilent (per-file start/completion lines), progress (bounded activity counts and diagnostics, default), or full-output (readable stream text under a per-file cap).

Rules enforced by the parser:

  • Review inputs must arrive together. A partial selection fails instead of degrading to context-only mode.
  • Unknown REDLINE_* variables are rejected, so typos fail loudly.
  • Review eligibility is resolved while building the context bundle, before this environment contract is parsed. It comes only from strict trusted-workflow JSON or .redline/review-eligibility.json at the exact base revision; see review eligibility.
  • Optional values are validated even without review execution.
  • When the whole-review deadline expires, Redline stops starting model calls. It records every remaining reviewed file as an explicit run-deadline-exhausted omission instead of silently dropping coverage.
  • Indexed-context path and repository identity arrive together. Configured context that is missing, invalid, stale, unsupported, or unavailable is recorded and degrades to file-only review instead of failing the run.
  • Review-reuse directory and namespace arrive together. Restored entries are untrusted and optional; invalid data degrades to normal per-file execution.
  • No variable accepts free-form review instructions.

Model configuration ​

REDLINE_MODEL_CONFIG is provider-neutral JSON with three required fields plus one optional auth field:

json
{
  "provider": "openrouter",
  "endpoint": "https://openrouter.ai/api/v1",
  "model": "z-ai/glm-5.3-flash"
}
  • provider — a short identifier, [A-Za-z0-9._-], at most 64 characters. It keys the credential map and names the provider inside harness configuration.
  • endpoint — absolute http or https URL of an OpenAI-compatible API. Loopback endpoints are permitted for local model servers and the CI mock endpoint.
  • model — the model identifier understood by the endpoint, at most 256 characters.
  • auth — optional; the only supported value is "none", the credential-less profile for endpoints that need no authentication. See local model runners.

There is no fixed-model allowlist and no provider-specific credential input.

Credential map ​

REDLINE_MODEL_AUTH maps provider names to credential values:

json
{
  "openrouter": "sk-or-v1-…"
}

Only the entry for the configured provider is selected; everything else stays host-side. The selected credential reaches the harness through the mechanism documented in harness executor — an environment variable for Pi, a mode-0600 generated config file for OpenCode — and never appears in prompts, logs, diagnostics, or published output.

When the model config declares "auth": "none", the credential map is not required and not consulted: no credential is selected and nothing reaches the harness. A supplied map is tolerated (not an error) because the action's review gate requires a non-empty model-auth; pass a placeholder map there.

Local model runners ​

Local runners that expose an OpenAI-compatible REST endpoint work through the same contract, with the credential-less profile — no paid API key involved:

RunnerEndpointModel id
Ollamahttp://127.0.0.1:11434/v1name:tag, for example qwen3:0.6b
LM Studiohttp://127.0.0.1:1234/v1model identifier shown in the server tab
llama.cpp serverhttp://127.0.0.1:8080/v1-m model name or -a alias
vLLMhttp://<host>:8000/v1served model name
bash
REDLINE_MODEL_CONFIG='{"provider":"ollama","endpoint":"http://127.0.0.1:11434/v1","model":"qwen3:0.6b","auth":"none"}'
REDLINE_MODEL_AUTH=''

Notes:

  • Each runner mounts the OpenAI-compatible API under /v1 — include the suffix.
  • Loopback (127.0.0.1, localhost) and private-network endpoints are accepted by the same endpoint validation as remote APIs.
  • A server that still checks the header (rare) instead takes a placeholder entry in REDLINE_MODEL_AUTH; the value is local-only.
  • Via the GitHub Action, keep supplying model-auth (a placeholder map) — the action's review gate requires it, and with auth: "none" the map is not consulted, so no credential reaches the harness.
  • Self-hosted CI runners can reach the local server directly, which is the intended production shape for private projects. The container-sandbox milestone will revisit isolation for untrusted environments.

CLI usage ​

The same contract drives the standalone CLI:

bash
node src/review/cli.ts --validate-only   # validate the environment only
node src/review/cli.ts                   # run the review

For standalone CLI use, opt into indexed context by setting both variables before running the review:

bash
REDLINE_CODE_CONTEXT=/absolute/path/code-context.json
REDLINE_CODE_CONTEXT_REPOSITORY=owner/repository

The review tool verifies repository and head identity, parses the exact artifact schema, and re-resolves each selected span from REDLINE_SOURCE_DIR. It never opens the provider database or invokes the provider.

Exit codes: 0 success (context-only or completed review), 1 review or bundle failure, 2 usage or validation failure. A review run exits 1 when no reviewed file produced a validated review — every file failed, timed out, or produced invalid output.
