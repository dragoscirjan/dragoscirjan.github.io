Search, concurrency, and recovery ​

issue_search uses a domain-owned SQLite FTS5 index and BM25 ranking across title, body, comments, and scalar metadata. Exact status/type/assignee/parent/location filters are applied. The raw query is byte-bounded before whitespace normalization. The effective row and output-byte budgets are the smaller of the call/retrieval values and the configured security ceilings. Direct-library budgets must be positive safe integers and fail before SQLite is opened. Candidate IDs and revisions are always hydrated from canonical YAML; cache content never becomes returned authority.

The disposable cache also contains lossless, bounded projections of exact revisions, metadata, persisted hierarchy and relationship edges, comments, and typed links. Health checks compare every structured row and count to the complete YAML snapshot in cancellable, aggregate-bounded keyset pages. Missing, corrupt, wrong-version, stale-digest, failed-integrity, max-age, or contradictory caches either rebuild atomically or return a stable ISSUE_CACHE_STALE/ISSUE_CACHE_REBUILD_REQUIRED error under stale_policy: fail.

All writes hold the repository authority lease, validate a complete proposed graph, and publish through a durable exact-revision batch. Recursive archive/restore moves the complete subtree. On the next lease acquisition repository-store recovers interrupted journals without overwriting operator changes. Resolve conflicts by inspecting Git and canonical YAML, then retry with the latest returned revision. Symlinks, hard links, special files, unsafe paths, portable path collisions, and configured resource-limit violations fail closed.
